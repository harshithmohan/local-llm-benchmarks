# Strata

[Niko1221/Strata](https://github.com/Niko1221/Strata), the pack engine on Rig 1; the notes below describe the current pin: app **0.2.22**, engine build `0.1.69`, control `0.1.69` ([rig1-3060.md](../rig1-3060.md)).

A llama.cpp-derived engine that runs [Qwen3.8-Flash-Next](https://huggingface.co/Qwen/Qwen3.8-Flash-Next) (~125B parameters, 24,576 routed experts, ~10 of them used per token) on one 12 GB consumer card, by splitting the work across the whole PC instead of fitting the model in VRAM:

- **GPU:** attention and DeltaNet mixers, the gated-residual weights, routers, shared experts, the output head, the MTP draft layer, the KV cache, and an **expert cache** that fills the rest of VRAM with the most-used experts and adapts to the conversation as it runs.
- **Host RAM:** every expert, pinned. The CPU computes the experts the GPU does not hold, in place and in parallel with the GPU.
- **SSD:** a 28.8 GB n-gram table, read a few rows per token through the OS cache.

The same engine builds for CUDA and HIP.

**Measured on Rig 1**: the GSQ-RCO `Q2_0` release of [Qwen3.8-Flash-Next](https://huggingface.co/Qwen/Qwen3.8-Flash-Next), on its own pack. The timing rows are on the model card ([Qwen3.8-Flash-Next](../models/rig1-3060/qwen38-flash-next.md)); the ctx/chunk ladders and `STRATA_*` A/Bs are in git history.

## Why it is not a `llama-server` build

- **The HTTP API is a separate process.** The `strata` binary is a stdio backend (`--serve`); a Python server (`serve/server.py`) spawns it and owns the OpenAI (`/v1/chat/completions`) and Anthropic (`/v1/messages`) routes, the conversation cache and the agent features (tools, MCP, reasoning). Run settings live in a JSON config - an `exe` plus its `args`, `cwd`, tokenizer, model name and log path - rather than on the server's command line, so the same settings can drive the CLI, the app and the server. The two are not combined: the server's own command line takes only server-level flags (`--config`, `--port`, `--host`, `--lazy`, `--idle-unload`, ...) and an engine flag passed there is a startup error, while the config is read as plain JSON with no includes or substitutions - so a change to an engine flag is always a change to the config file, and a second configuration (a longer window, say) is a second file.
- **The model is a pack, not one GGUF.** `--pack DIR` holds a per-layer index, the dense weights and a tokenizer; `native_experts.txt` says where each expert's rows live, and an optional `experts.bin` maps them for low-RAM machines. The original GGUF shards stay on disk and are named separately (`--native`, `--ple-gguf`).
- **Its own flag vocabulary** - the mapping to the llama.cpp names is below. Only `--rope-scaling` and its companions, plus the sampling flags, keep the llama.cpp names.

## Flags

Flags used on this benchmark:

- `--pack DIR` - the pack directory (per-layer index, dense weights, tokenizer, expert map).
- `--native SHARD1` - the first model GGUF shard; turns on every "native" (precomputed, GGUF-mapped) path at once: stream-token, head, dense + PLE projections, MoE combine, GDN, router, QSA, indexer, RoPE and the CPU `q8_0` contract. The individual `--native-*` flags stay for A/B runs, and `--no-capture` runs the layers directly instead of replaying graphs.
- `--ple-gguf PATH` - the shard holding the per-layer embedding table (the PLE layer). Which shard that is depends on the pack's layer split and is not always the second: a release can keep all layers in shard 1 and put the table alone in shard 2, or break earlier and carry the table in shard 1. Left unset it defaults to the shard that holds `per_layer_token_embd.weight`, found by name - as are the model's shards themselves, by their `<name>-0000N-of-0000M.gguf` names beside `--native` (a missing shard is an error).
- `--expert-profile P` - pre-loads the VRAM expert tier from a saved `profile.bin` instead of admitting on first use.
- `--expert-cache N|auto` - expert blobs kept resident in VRAM (`0` = off). `auto` sizes the tier from the VRAM left after the weights, session buffers and KV.
- `--mtp DIR` - the MTP runtime directory (the draft layer's weights and `draft_vocab.bin`).
- `--spec T` - the speculative verify window. `T >= 2` is structural on this pack: a native (IQ) pack refuses to start at `--spec 1` (it needs `--native SHARD1`, `--spec T` with `T >= 2`, and `--prefill CHUNK`), and `--mtp` is ignored when `T < 2`.
- `--spec-min-p F` - the draft acceptance floor (default 0.0). At `0.0` the verify window is always the full `--spec`; above it the window is truncated to the run of leading drafts whose probability clears `F`. Sweep it with `--spec` ([tuning.md](../tuning.md#strata-only)).
- `--prefill CHUNK` - batched prompt processing in chunks; `auto[:N]` picks the largest chunk whose buffers the expert cache can lend (needs `--native`). The prompt path borrows the top of the expert cache for its per-chunk buffers and refills those slots after each chunk, so a bigger chunk borrows more: `auto` takes the largest chunk whose buffers leave `>= 128` cache slots free and take at most `90%` of them - `85%` when under 90% of the expert bytes are pinned host RAM. The scan is a bisection on the 256-token grid and holds the prompt ring full, so the value it lands on is pack-specific and can sit between the list's sizes (`8192`, `6144`, `4096`, `3072`, ...). On NVIDIA cc 8.0+ a bare `auto` may take chunks up to `32768`, and the load prints that ceiling; `STRATA_NV_CHUNK=0` caps it at `8192` and `=16` at `16384`, while `auto:N` pins N directly. On our 204800 shape `auto` lands at `3584` on the DFlash2 entry (1804 slots / 2.97 GiB) and `2304` on the MTP entry (1536 slots / 2.53 GiB). The served configs pin `--prefill 6144` and `4864`, which re-sizes the cache to fit: 3147 slots / 5.14 GiB, borrow 2211, and 2990 slots / 4.89 GiB, borrow 2006. An explicit `--prefill N` is the operator's number, which only has to fit - the percentage is an `auto`-only rule, so an explicit chunk never consults it and can be larger than `auto` would pick on the same cache. An oversized pin is clamped rather than rejected: it is halved until it fits, so an explicit chunk lands on the pin or one of its halves. The percentage is a share of the *resident* cache, not of free VRAM, so `--expert-cache N` moves the step; the cache shrinks as `--max-context` grows, so the chunk steps down with it, and each step down costs prefill. `STRATA_PREFILL_LEND_PCT=N` overrides the percentage and lets a larger chunk fit a wider window; wherever the chosen chunk does not change it does nothing. `STRATA_NV_CHUNK=0` does not move `auto` on this shape, so the 32768 ceiling is not what binds. The A/Bs are in git history. The auto cache reserves 700 MiB of the card (its `--vram-reserve-mib` default), plus allowances for the draft head and for what is allocated after the cache.
- **The small-expert-cache prompt path** - below an 8192-token chunk the engine logs `strata serve: small expert cache: ...` and reads prompts with the unfused experts and, from two chunks, the layer-major walk. `STRATA_PF_SMALL=0` suppresses it and keeps the normal path, and `STRATA_PF_FUSED` / `STRATA_PREFILL_LAYER_MAJOR` set by hand still win; it is worth ~12% prefill on the 10k prompt at the 204800 shape. Measured rows on the [model page](../models/rig1-3060/qwen38-flash-next.md).
- `--kv fp16|int8|q4_0|k8v4` - KV storage. `int8` is int8 codes with an fp16 scale per 64 values (half of fp16); `q4_0` is a Hadamard-rotated 4-bit K/V; `k8v4` is INT8 K with a rotated `q4_0` V.
- `--max-context N` - KV/state capacity (default 4096). The pack's trained window is what it should stay within unless `--rope-scaling` is used. Size it to what you serve: at a fixed chunk and expert cache, raising the window alone still costs prefill even though the same prompt is read, so headroom you do not use is not free.
- `--prompt-cache N` - how many conversation checkpoints the server keeps between requests (default 6, ~118 MB of RAM each; `0` = read every prompt from the start). This is what makes a resent prompt cheap - the second pass reports a nonzero `cache_n` - and it is an engine flag, not a request field. `--prompt-cache-every N` also checkpoints every N fresh prompt tokens (default 16384, `0` = off). Checkpoints land only on prompt-chunk boundaries, so the spacing that matters is `ceil(N / chunk) x chunk` - the default 16384 is several chunks apart - and a growing session pays that gap on every turn. Pinning N to the chunk minimises the per-turn re-read, and the grid cannot be finer than one chunk, so the chunk size is the optimum. The measured ladder is in git history.
- **CUDA switches are a default table on sm_86, not a per-switch opt-in.** With an sm_86 device visible and the variable unset, 0.1.69 turns on **17 speed switches** and logs `strata: sm_86 (Ampere): 17 speed switches on by default …`: `ADAPT_LAG CPU_IQ_ALL_EXACT1 SIDE_MIXER ATTN_DAILY GR_UP75 GU_SWIGLU QSA_ROWS B6_MMVQ_ROWS DEQUANT_SIDE LFUSE PLE_COMPACT PLE_COPY_STREAM HC_UPMIX Q80_ROWS1 EXP_MODE PREFILL_CPU_SHARE_NT ADAPT_FETCH`. `QFUSE` is no longer default (opt-in only; upstream measured a partial-VRAM decode regression), and `ADAPT_FETCH=2` is auto-enabled on sm_86/sm_89 at ≤13 GiB. A variable we set wins over the table, `STRATA_SM86_PERF=0` disables the whole thing, and the stack is bit-exact apart from `QSA_SPLIT_ATTN` (rounding-level: KL 0.0016 against the bit-exact floor of 0.0012) and `ADAPT_FETCH` (the engine says it does not give bit-for-bit identical text; `STRATA_ADAPT_FETCH=0` disables). Hand-set, the decode switches improved decode on the 10k prompt with prefill and VRAM unchanged. Our entries set `EXPDEC`, `QSA_SPLIT_ATTN`, `PREFILL_LEND_PCT` and `KEEP_EMPTY_TURNS`; the route prior and the small-cache path have their own bullets.
- **Route prior on small cards** - a multiplier the engine applies to its expert re-ranking on discrete CUDA cards at ≤13 GiB, off by default. Upstream keeps it off because reports and their own checks tied it to repeated text in long sessions - the faster routing is suspected of looping in long agent sessions. The quality evidence on a 3060 was thin either way: 80 tasks with no copy or code errors, but agent loops finished slightly less often (4.5 of 10 pass over 4 runs on, against 5.6 over 7 runs off, where the off runs alone ranged 4 to 6 - inside the run-to-run spread), and a stronger 2.0 showed copy and code defects, which is why 1.5 is the value to use. Off it costs ~18-20% decode on the 12 GB card and prefill is unchanged, so our configs set `STRATA_ROUTE_PRIOR=1.5`. This is the one output-shaping switch - answers can differ slightly rather than only speed - so `STRATA_ROUTE_PRIOR=0` is the single-switch way to disable expert re-ranking if its output is ever suspect. Our rows at 1.5 (2026-11-03) are single-turn 512-token passes, so they cannot show long-session repetition - that risk is carried unmeasured. Measured A/Bs on the [model page](../models/rig1-3060/qwen38-flash-next.md).
- **`STRATA_ROUTE_TAIL_SKIP=7` is on by default** - a missed expert that every token of a verify window routes at rank 7 or lower is skipped, which upstream puts at +10..20% decode on 12-16 GB cards that miss experts. Like the route prior it **changes answers** ("answers differ slightly from the default"); `STRATA_ROUTE_TAIL_SKIP=0` turns it off. The serve log states it at startup and every stats line reports `route tail skip: N missed experts skipped (M entries)`.
- **`--vram-reserve-mib N`** - VRAM kept clear of the expert cache (default 700). On the 12 GB card the served cache ends 830-920 MiB below the limit depending on the drafter, and the engine warns per request that anything below 512 MiB risks the driver paging GPU memory (#2065); its own remedy is `--vram-reserve-mib 768`. The reserve has not been raised here: a 194,545-token prompt (95% of `--max-context 204800`) held a steady 421 MiB free for the whole 200 s prefill and decoded at 50.5 tok/s with no paging, so the floor did not bite at the window we serve.
- **`--mtp-draft-vocab FILE`** - the draft head's token subset, read instead of `<mtp>/draft_vocab.bin`. The bundle's default is the English/code subset plus the whole CJK block (106,299 rows, a 178 MiB head); `data/draft_vocab_en.bin` is English and code only (40,525 rows, 68 MiB), `draft_vocab_cyrillic.bin` adds the Cyrillic script (58,963). On Rig 1 (2026-10-28) the `en` subset moved 110 MiB off the draft head into `--expert-cache auto`, which spends it on slots: 1719 -> 1784 cache slots, borrow 1541 -> 1654, prefill 997.0 -> 1078.0 tok/s at 10k (+8.1%) and 1032.8 -> 1048.6 at 60k (+1.5%), decode inside the spread of both arms, draft acceptance down ~4 points. Free VRAM after load is unchanged (460 -> 458 MiB): the auto cache reinvests the saving, so this buys cache, not headroom. Cost is structural - a token outside the subset can never be drafted, which for `en` means CJK and Cyrillic output decodes without MTP.
- **`--draft mtp|dflash2` + `--draft-model PACK`** - picks the single drafter (one per run, never two). `--draft dflash2` still requires `--mtp-draft-vocab FILE` and `--spec >= 2`, and drops the MTP layer entirely under `--draft-fallback none`; under `--draft mtp` both load, and MTP takes over if DFlash2 cannot start. On this card DFlash2 is the smaller drafter by a wide margin - `strata dflash2: … drafter 478 MiB of VRAM (Q4_0 weights)` against `strata mtp: draft layer loaded, 837 MiB` - so the DFlash2 entry's pinned cache lands at 3147 slots against 2990 for the MTP entry, and prompt prefill gains at every depth, while decode stays inside its own run-to-run spread. The engine says the opposite out loud at load (`on a 12 GB NVIDIA card the MTP drafter was faster in most measurements`), which is true of decode and not of prefill. The serve layer adds two traps of its own: it only counts the drafter as downloaded when `dflash2/qwen3.8-flash-next-dflash2.q4_0.pack` exists under that exact name, and `terminal/serve/drafting.py` restricts the family list to `("qwen","gyro","unsloth")` and strips hand-set flags - so a Swift fine-tune asked for DFlash2 ends up with no drafting at all. Packing: `--q4_0-selector` also quantizes the matrices (Q8_0 needs pack-then-`--convert-selector`); Q4_0 matrices measure at 478 MiB VRAM / 324 MiB on disk against 705 MiB / 551 MiB for Q8_0, and the Q4_0 arm took the larger cache. Rows: [model page](../models/rig1-3060/qwen38-flash-next.md). The selector also takes the serve layer's `Auto` and `Off` names, with DFlash2 the default when nothing is pinned; both served configs pin one drafter by hand, and on sm_86 the draft window and confidence come from our explicit `--spec` and `--draft-conf` rather than from the card-class defaults. The selector pack upstream ships is `qwen3.8-flash-next-dflash2.strata1.q4_0-selq4.pack`; we serve the locally built `q4s` pack instead.
- **Untried but measured upstream on a 3060**: `--slots 2` (+10-12% decode). `--kv q4_0` "did not reproduce a gain" at 12 GB; `--prefill auto:32768` is upstream's recommendation for a 64 GB+ host and is not what our selection picks, because the 12 GB card's expert cache caps the chunk well below it even with 128 GB of RAM; `--pcie-frac` above ~0.75 and route prior 2.0 are on upstream's don't list.
- `vision` (config key) + `--vision` (flag) - image input. The `vision` object names the encoder (`exe`, i.e. `strata-vision`), an `mmproj`, the `model` (the native shard) and `gpu`/`max_tokens`/`min_tokens`/`threads`; the flag turns the image path on, and without either an `image_url` part is rejected ("this server was started without the vision encoder"). `max_tokens` caps the tokens a picture is turned into and `min_tokens` floors them - leaving `min_tokens` unset keeps small pictures cheap (~300 tokens for 640x480) and reads them better than padding them up to the cap. `"gpu": true` runs the encoder on the card (it holds ~1.4 GB of VRAM, and the server then adds `--vram-reserve-mib 700` to the args); `"gpu": false` runs it on the CPU, which is what a 12 GB card wants. Encoder tests and the measured text-path cost are in git history.
- `sampling` (config key, not a flag) - a JSON object with `temperature`, `top_p`, `top_k`, `min_p`, `presence_penalty`, `repetition_penalty` and `seed`. The served path ignores the sampling flags on the command line, and its base default is **greedy** (`temperature 0.0`) - a served config therefore sets this object. Since 0.2.22, Flash-Next/Gyro entries started with `--mtp` use the config's `sampling` again for a request that names no sampling (#7070); Qwen3.6 stays greedy. Only non-default values are forwarded to the backend, and a request field still overrides it.
- `env_to_user` (config key, not a flag) - off by default; the served configs set it `true`. When a request's first system message carries an `<env>` block, that block is moved to the front of the first user message instead, so the system prompt stays byte-identical across sessions and the disk prefix cache can restore it rather than re-reading it on every turn - a changed working directory or date would otherwise invalidate the whole prefix. The model sees the same lines one turn later, and a request without that block is unchanged.

### Against the llama.cpp engines

| Concept | llama.cpp | Strata |
| --- | --- | --- |
| context | `-c` / `--ctx-size` | `--max-context` |
| KV type | `--cache-type-k/-v` (`q8_0`, `q4_0`) | `--kv fp16\|int8\|q4_0\|k8v4` |
| prompt batch | `-b` / `-ub` | `--prefill auto[:N]` (needs `--native`) |
| expert cache | `--moe-expert-cache-size` ([moe-cache fork](moe-cache-fork.md)) | `--expert-cache N\|auto` (+ `--expert-profile`) |
| spec decode (MTP) | `--spec-type draft-mtp --spec-draft-n-max` | `--mtp DIR --spec T --spec-min-p F` |
| context extension | `--rope-scaling yarn --rope-scale F --yarn-orig-ctx N` | same names |
| sampling | `--temp` / `--top-p` / `--top-k` / `--min-p` / `--presence-penalty` / `--repeat-penalty` / `--seed` | config JSON `sampling` object (`temperature` / `top_p` / `top_k` / `min_p` / `presence_penalty` / `repetition_penalty` / `seed`) |

Known issue: [issues.md](../issues.md) §7 - a reasoning-only assistant turn is dropped from the prompt. Upstream also reports `conversation snapshot: invalid K/V extent` on runs with no MTP drafter, which is the DFlash2-only base entry's shape; it has not been seen on this deployment.

## Validation

The engine prints one line per request - `request prompt P cached C output O prompt_read R ms total S ms prefill X tok/s decode Y tok/s` - and the server returns the same numbers in the response's `timings` object **under llama.cpp's field names**: `prompt_n`, `prompt_ms`, `prompt_per_second`, `predicted_n`, `predicted_ms`, `predicted_per_second`, `cache_n`, plus `draft_n` / `draft_n_accepted` when MTP reported them. `cache_n` is the part of the prompt answered from Strata's own conversation cache and `prompt_n` is the rest, so a pass that reports a nonzero `cache_n` is not a full prefill - and that cache engages on its own: send the same prompt twice and the second pass comes back with a nonzero `cache_n`, with no cache parameter set on the request.

The request protocol in [methodology.md](../methodology.md) does **not** carry over as written: Strata serves no raw `/v1/completions` route - only `/v1/chat/completions`, `/v1/messages` and `/v1/responses`, so a chat template is always applied - and it ignores both `cache_prompt` and `ignore_eos`. **Run every prefill measurement with `--prompt-cache 0`** - that reads each prompt from the start rather than resuming a checkpoint - and treat a pass as a full prefill only when `cache_n` is 0. Only a `predicted_n` that reaches the requested window is a complete decode run. There is no `llama-bench` equivalent, and `llama-bench` is not used anywhere here. Speed rows add `temperature: 0` only; leave reasoning effort and the rest of the sampling block as served. Quality/serving checks keep the config sampling.

The recorded rows use `--prompt-cache 0` as always, with `STRATA_ROUTE_PRIOR=1.5` and `STRATA_PF_SMALL=0` in the served env and the 0.1.69 default table (including `ADAPT_FETCH`); the drafter is named per table (MTP or DFlash2, one per run), and the measured rows themselves stay on the [model page](../models/rig1-3060/qwen38-flash-next.md).

Served without an API key, the server also refuses a request whose `Host` is not a name it answers to (403, DNS-rebinding protection): an IP address, `localhost` and the names it already answers to pass, and any other name must be listed in the config's `allowed_hosts` - which includes the name a proxy or gateway forwards, since it passes the `Host` header on.

A load is valid when the startup log names a nonzero VRAM expert tier (the engine warns when the weights leave no VRAM for the cache) and the CPU/GPU split actually happens; `--dump-routing PATH` writes the routed expert ids and weights per layer and position when the split needs checking, and `--expert-cache-cpu-order` makes the GPU's reduction follow the CPU's order for an A/B.
